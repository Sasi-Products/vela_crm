# Vela Spinners Web Admin Panel

React + Vite admin panel for the supplied Vela Spinners backend.

## Stack

- React 18
- React Router 6
- Axios
- Tailwind CSS **3.4.17**
- Lucide icons
- React Hot Toast

## Run

```bash
npm install
cp .env.example .env
npm run dev
```

Default API:

```env
VITE_API_BASE_URL=http://localhost:8080/api
```

The supplied backend already allows `http://localhost:5173` in its default CORS list.

## Main modules

- Authentication & profile
- Dashboard
- Units
- Admin / Employee users
- Granular user permissions
- Global parties
- Items / HSN / stock tracking profile
- Price lists
- Outward Delivery Challans
- DC Super Admin approval / rejection
- Tally invoice linking and PDF viewing
- Purchase DC / Inward
- Supplier invoice PDF attachment
- Purchase approval / rejection
- Stock summary
- Stock ledger
- Audit logs

## Permissions

The original `backend(1).zip` uses role-only middleware and has no persisted permission column/API. Therefore true Super-Admin-managed granular permissions cannot be securely implemented in the browser alone.

Use the accompanying **Vela backend permission update**. It adds:

- `users.permissions` JSON column
- `GET /api/admins/permissions/catalog`
- `PUT /api/admins/:id/permissions`
- permission checks on dashboard, parties, items, price lists, DC, Purchase DC, invoice viewing and stock routes
- Super Admin bypass for every permission
- Super-Admin-only approval, rejection, Tally linking, user suspension and audit operations remain hard protected

The web app has a compatibility fallback for the original role-only backend, but persistent permission assignment requires the updated backend.

## Permission behavior

Super Admin always sees every module.

Admin and Employee navigation is generated from the permissions returned by `/api/auth/login` and `/api/auth/profile`.

Examples:

```text
dashboard.view
parties.view
parties.create
items.view
prices.view
dc.view
dc.create
purchase.view
purchase.create
purchase.upload_invoice
invoices.view
stock.view
```

## Document behavior

Outward DC:

- DC number is generated by the backend (`U1/26-27/DC-001` etc.)
- Browser print layout contains no rate / price / total
- Driver Sign, Party Seal & Signature and Vela Spinners signature areas are included
- Only Super Admin can approve/reject and link a Tally invoice

Purchase DC / Inward:

- Purchase DC number is backend-generated (`U1/26-27/PUR-001` etc.)
- Supplier invoice PDF can be attached
- Approval posts stock IN

Tally Invoice:

- App stores Tally invoice metadata/PDF only
- The app does not generate a priced sales invoice PDF

## Production build

```bash
npm run build
```

Deploy the `dist/` folder to your web server and set `VITE_API_BASE_URL` to the live backend before building.
